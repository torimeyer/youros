## Gap Detail: Reaper Sweep Blocking

**Root cause (still present on main):**
`_do_sweep` calls `detect_stalled_agents(get_worktree_head=_worktree_head_hash)`.
`_worktree_head_hash` runs `subprocess.run(["git", "rev-parse", "HEAD"], timeout=2)` synchronously
on the event loop for every running worktree agent, every 30s.

With N running worktree agents, each sweep blocks `accept()` for up to N×2s.
After a long idle window where agents remain in "running" status but go quiet,
the reaper fires repeatedly with these blocking subprocess calls — matching the
TCP timeout / health probe failure pattern in →1166.

**Fix (not on main):** commit 97bbabe extracted `_do_sweep_sync` and wrapped it:
```python
async def _do_sweep() -> int:
    return await asyncio.to_thread(_do_sweep_sync)
```
This was only committed to `worktree-agent-diagnose-fix-api-agents-wedge-11-c0b856`.

**SWEEP_INTERVAL check:** SWEEP_INTERVAL=30s, cache TTLs=60s, flush=25s. These are
no longer synchronized (was 30s/30s/30s before →1192). The collision is fixed.
But the subprocess-on-event-loop issue remains regardless of timing.
