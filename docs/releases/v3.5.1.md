# myOS v3.5.1

Security patch. No new features.

## What changed

**Removed a leaked Stitch API key from the repo.** A Google Cloud API key for the Stitch MCP server was being tracked inside `.mcp.json`. Google Cloud's security scanner flagged it as exposed in the public repo and will auto-delete the key. The key is now rotated out, the old one is dead, and the file that held it is gitignored going forward.

**`.mcp.json` is now a per-user local file.** The tracked file is `.mcp.json.example` — a skeleton with a placeholder where your Stitch API key goes. `install.sh` seeds `.mcp.json` from the example on first install so every user gets a working config to edit with their own key.

**Pre-commit hook now blocks secret leaks at the source.** If you try to commit a file that contains an obvious API key pattern (Google `AIza...`, Stitch `AQ.Ab...`, AWS `AKIA...`, Anthropic `sk-ant-...`, OpenAI `sk-...`, or a PEM private key block), the hook rejects the commit with a clear message. Bypass with `git commit --no-verify` if it's a test fixture.

## How to update

```
cd ~/myos
./update.sh
```

After updating, your local `.mcp.json` is untouched. Paste your own Stitch API key into `.mcp.json` if you use the Stitch MCP server. Other MCP servers work without any change.

## If you cloned before this patch

Your local `.mcp.json` may still hold the leaked key. Replace the `STITCH_API_KEY` value in `.mcp.json` with a fresh key from Google Cloud Console. The old key is being deleted by Google, so Stitch will stop working until you rotate.
