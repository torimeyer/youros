# yourOS v3.11.0

**Five new templates, six sharper rewrites, and a batch of behind-the-scenes coordination fixes.** This is the biggest template drop since launch, plus the spec wizard gets a smoother entry point and Gemini finally speaks as itself.

## What's New

### Five new agent templates
Campaign Brief, Budget Builder, Investor Update, Customer Reply, and Design Critique are now built into the template picker. Each one covers a common workflow that previously needed a custom template — marketing, finance, founder updates, support, and design review.

### Six template rewrites
Six existing built-in templates (across research, analysis, and build categories) got rewritten descriptions and tighter prompts. They now do a better job explaining what they do before you launch them, and produce more focused results when you do.

### New Spec goes straight to the wizard
Clicking New Spec used to open a blank name field first. Now it opens the step-by-step wizard immediately. One less click, no blank-slate anxiety.

### Gemini has its own identity
When you switch to Gemini in chat, it now introduces itself as Gemini instead of taking on the yourOS persona. Each AI speaks as itself. The default assistant still has the full yourOS persona.

### ALIASES directive on agent files
Agent template files now support an `ALIASES` directive. A template can be found under any of its listed alternate names in the picker and command bar. Useful for templates with long official names or ones that fit multiple workflows.

## Under the Hood

### Cross-session cancel guard (→958, →959)
`POST /api/agents/<name>/cancel` now checks whether the cancellation request comes from the same Claude session that spawned the agent. Agents running in a peer session can no longer be bulk-cancelled by a different session. Spawn provenance fields (`session_id`, `message_id`) are stored on every agent row at registration time.

### Spawn provenance forwarded end-to-end (→961)
The task-isolation-bridge hook now reads the parent session's `CLAUDE_SESSION_ID` from the environment and forwards it in the spawn payload. The backend stores it on the agent row, so every agent can be traced back to the session and message that created it.

### Structured hook deny logging
All PreToolUse hooks now use a shared `lib/deny.sh` helper. Every deny writes a JSON line to `~/.claude/logs/hook-denies.log` and the most recent denies surface in the standing-rules header shown at the start of each turn. No more wondering why a tool call was blocked.

### Settings-level deny detector
A new `permission-deny-detector.sh` hook distinguishes between denies that came from a PreToolUse hook script and denies that came from a `permissions.deny` rule in settings. The two failure modes now have separate log entries and separate copy in the standing-rules header.

### EXIT traces on all PreToolUse hooks
All 8 PreToolUse hooks now emit an EXIT trace line so it is clear which hook ran, whether it allowed or denied, and at what wall-clock time. Useful when two hooks fire on the same tool call.

## Bugfixes

- The `elit_agentfile_alias_exists` test was targeting the wrong agent file. It now correctly points at `explain-plain.agent`, which carries the `ALIASES` directive that the test exercises. (→960)

## For Developers

- `lib/deny.sh` is now the standard deny helper for all hook scripts. Drop it in and call `deny "reason"` instead of writing your own JSON output.
- `permission-deny-detector.sh` is registered in `.claude/settings.json` as a PostToolUse hook and logs to `~/.claude/logs/permission-denies.log`.
- `task-isolation-bridge.sh` forwards `session_id` from the environment into every spawn payload. Downstream consumers can read `agent.session_id` from the agents API.
