# v4.1.0 Release Notes

**Released:** 2026-05-29
**Branch:** fix-1806-backend-loop-forks (v4.1.0)

---

## Highlights

- **"Tasks" is now the word.** Everything that used to say "needle" in the app now says "task." Labels, buttons, tabs, API calls, hooks, and docs are all consistent. The →NNN reference numbers stay the same.
- **The backend restarts itself.** If yourOS crashes, launchd brings it back automatically. No more manual restart after a bad shutdown.
- **ToriChat can dig deeper.** The wall that stopped ToriChat after 6 tool rounds is gone. It now goes up to 15. Semantic search is also available as a native tool so the model can search your codebase directly.
- **Drive opens faster.** The Drive service is now cached and the initial file load runs in parallel. First load is noticeably quicker.
- **Several frustrating bugs fixed.** Blank app on refresh (Vite 8 stale chunks), sidebar covering content instead of pushing it aside, and chat tabs bleeding into each other are all gone.

## What's new

### ToriChat goes deeper
The hard cutoff at 6 tool rounds is raised to 15. ToriChat can now follow a thread of searches and lookups much further before stopping. Semantic search is also exposed as a direct tool, so the model can search your codebase as part of a conversation without needing a separate step.
References: →1785, →1786, →1787

### yourOS stays up on its own
The backend is now managed by launchd with KeepAlive turned on. If the backend process dies for any reason, launchd restarts it automatically. A separate kill-only watchdog is also installed. You no longer need to manually bounce the server after a crash.
Reference: →1744

### Specs have IDs
Every spec now gets a sequential ID in its header (S001, S002, ...). The ID shows as a badge on the Specs page and you can use it directly in the CLI. A backfill script assigns IDs to any existing specs that predate this change.
Reference: →1784

### Sidebar pushes instead of overlaying
Opening the sidebar used to cover your content. It now pushes the main panel to the side, keeping everything visible.
Reference: →1780

### Chat tabs are fully separate sessions
Each chat tab is now its own isolated session. Opening a second chat no longer bleeds context from the first one into replies.
Reference: →1782

### Jira inline comment
You can now reply to Jira tickets directly from the Jira detail page inside yourOS. The reply button was accidentally removed in a previous release and is back.
Reference: →1772

### Drive loads faster
The Drive service is cached after the first call and the cold path metadata and export requests run in parallel. The first time you open Drive in a session is meaningfully faster.
Reference: →1755

### Discord spec written
The groundwork for connecting Discord as a service is documented. Not yet live, but the spec is complete and follows the same shape as the Slack integration.
Reference: →1706

### Design guardrails tightened (for agents)
Three project-local skill overrides now enforce the three-signal check before any new file is written. Agents must check whether a file already exists in the codebase, in git history, and in the spec backlog before proposing to create one. Three bugs in the pre-design-audit script were also fixed.
References: →1790, →1791, →1793, →1795, →1796, →1797

### Plain-language rules guide
A guide for writing user-facing text without jargon is now at `docs/rules-plain-language.md`. Written for contributors and agents alike.
Reference: →1732

## Renames

### Needles are now tasks

The biggest change in this release is invisible in the product but significant under the hood. The word "needle" has been replaced with "task" everywhere yourOS owns the surface: the app labels, backend API parameters, hooks, CLAUDE.md vocabulary, and all documentation.

**What you will notice:**
- The app says "tasks" where it used to say "needles" (sidebar nav, search filters, modals, buttons, page headers)
- The `/needle` slash command is now `/task`
- The "Sweeps" and "Haystack" concepts in the Tasks page are gone. They have been replaced with simpler labels.
- The SpecWizard sends `kind: "task"` instead of `kind: "needle"` to the backend

**What stays the same:**
- The →NNN reference numbers are unchanged
- The `.ostk/needles/` filesystem path is Scott's territory and is not touched
- The `needle_id` internal identifier field is kept for now (a one-release deprecation window; will be renamed in a later release)

This rename was done in 6 phases across frontend, backend, hooks, CLAUDE.md, docs, and memory files. Commits: 200171d1, 0ca7a7ae, 021e0418, d9bcc229, e1a47478, d3bc8246.
References: →1788, →1789

## Known follow-ups

These tasks did not land in v4.1.0 and carry forward:

- **→1775 (P1):** Worktree cleanup. The reaper dry-run found 0 absorbed worktrees, so running it now would delete nothing. About 15 worktrees have uncommitted changes that need review first. This is a planned cleanup step, not a blocker.
- **→1754 (P2):** Test isolation. A singleton leak in `services.ostk.ostk` means some tests share state when run together. Tests pass individually; this is a reliability improvement.
- **→1765 (P2):** A regex in the receipts gate can produce a false positive on backtick-wrapped commit hashes. Does not affect correctness, just occasional unnecessary warnings.
- **→1800 (P3):** A hook test file references the old `needle-hygiene.sh` path which no longer exists after the Phase D rename. Needs rewrite or deletion.
- **Slack token refresh (P2):** The deeper Slack improvements (automatic token refresh and 12-hour expiry handling) are staged but not in this release. Basic paste-the-token connect works today; the refresh rotation lands in a follow-up.
- **Spec task counts (P2):** Some specs can still show a 0 of N count when their linked tasks live in the rotated task archive. A targeted fix is staged for a follow-up.
