# v5.6.4 — Atlassian: Jira and Confluence on separate sites now work correctly

## What changed

If your Jira account lives at one Atlassian site and your Confluence account lives at a different Atlassian site, the app now connects to each one correctly.

Previously, the app stored a single "which Atlassian site are you on" value and used it for both Jira and Confluence. If the two products were on different sites, one of them would fail silently with the wrong connection.

## What's fixed

- The app now stores a separate site reference for Jira and for Confluence after you connect.
- When you connect via the OAuth button in Settings, the app passes both site addresses through the connection flow and saves each one independently.
- If you only have one Atlassian site for both products, nothing changes for you.

## How to apply

If you were seeing Jira or Confluence failing after connecting Atlassian, go to Settings and click "Reconnect Atlassian." The reconnect flow will now save the correct site for each product.

## Files changed

- `api/services/atlassian.py` — reads and writes per-product site identifiers
- `api/routers/atlassian.py` — passes site params through the OAuth flow; picks the right site per product in the callback
- `app/src/components/AtlassianConnect.tsx` — both connect and reconnect buttons pass current site values
- `api/tests/test_atlassian_oauth.py` — 7 new tests covering the dual-site logic
