### ADHD-mode self-healing

ADHD mode used to require the model to manually arm a Monitor before every Agent spawn. That coupling was fragile: Monitor's pre-tool hooks take 200-500 ms, and the harness cancels any pending tool the moment you type. So every Agent spawn could die from a stray check-in.

- **Root cause traced and fixed**: ADHD's pre-agent check now auto-arms the watchdog itself instead of denying. The model no longer has to call Monitor for supervision to work. (See →1563 root-cause doc + commit `2c95ae4`.)
- **Backend-probe retry**: the pre-agent guard now retries on transient backend blips instead of denying outright.
- **ADHD pairing deny gives better hint**: when a deny does fire, the message suggests the canonical `monitor-agent.sh` helper.
- **Monitor "internal error" identified**: the harness emits "[Request interrupted by user for tool use]" when you type during a tool's pre-hook window. Surfaced as "Tool result missing due to internal error" in the UI. Not a bug, but documented so it stops being treated as one.

## Diagnoses landed

- **→1563 Monitor "internal error" root cause**: not a multi-tool-storm bug as previously hypothesized. It's user typing during the pre-tool hook window.
- **Tool cancellation pattern (bash + Monitor share the mechanism)**: report at `docs/draft/_review/2026-05-21-tool-cancellation-pattern.md`. Tier-1 fix landed: new standing rule that says use `mcp__ostk__spawn` for any bash command >10s, so user messages can't interrupt them.
- **→1587 agents look stuck**: root cause was the transcript file only captures plain-text model output, not tool calls. Long-running vitest via bash hit the 30s tool socket timeout. Subagent prompt template updated with three new lines: heartbeat current_step, use spawn for tests, skip pre-existing failures.
