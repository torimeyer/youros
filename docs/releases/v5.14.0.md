The dashboard now answers "what do I have to work on" straight from Jira and Confluence. The Jira card groups your tickets by status with overdue ones first, shows due dates in plain words, counts what's overdue right in the header, and can add a ticket to your tasks with one click. The Confluence card lists the action items assigned to you, lets you check them off in place, and shows where you've been mentioned. Six ready-made question cards are available too; they're off by default and can be switched on from the customize dialog.

Chat can now use tools you've explicitly approved. Each connected tool in settings has a new "Allow in chat" checkbox; tick it for something like Slack and chat can read from and act on that service, while everything unticked stays blocked exactly as before. The settings screen explains what allowing means, and the privacy page now says plainly that an allowed tool's requests leave your laptop.

Your settings now stay exactly as you set them. A family of quiet bugs let screens write values back to the server that they had only meant to read: opening settings could overwrite a just-saved OS name, accent color, default model, or terminology choice with an older one; the welcome wizard's first moment on screen could blank your OS name entirely, even resetting it to the factory default; and pressing Enter right after typing a new OS name could save the previous name instead of the one you typed. All of those paths are fixed with regression tests, and the welcome wizard also no longer traps someone who is already set up: if the app can't reach its backend right away it now quietly keeps retrying and dismisses the wizard the moment the server confirms you're set up. One last timing gap is closed as well: on a busy machine, the app's own catch-up reads could answer with a moment-old copy of your settings and quietly undo a change you had just made. The app now refuses to apply any fetched setting that would overwrite a change still on its way to the server. And the last piece: a save that gets lost on the way to the server is now retried instead of assumed delivered, a save that truly fails tells you so in plain words instead of staying silent, and closing the settings screen no longer quietly re-saves an old value over a newer change made elsewhere.

Your saved keys and tokens stay on your machine. The settings screen already masked your saved keys; now the connected-servers list does too, showing only the last four characters of a connection token with a simple saved-or-not indicator, while saves keep working unchanged.

Sturdier machinery underneath: the sidebar badge now counts work that's actively in progress, not just waiting; the cancel-everything button no longer rewrites the history of helpers that had already finished; a helper that goes quiet is only marked finished after a real liveness check instead of being assumed done; the frontend server can no longer freeze on its own log output and now always leaves a log file and recovers from crashes and freezes; and the pre-release checks got honest, they start with a fresh browser helper every run, fail loudly instead of skipping when something they need is missing, and never "restore" a settings value they didn't actually capture.
