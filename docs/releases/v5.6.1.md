# v5.6.1 — Patch: Atlassian probe timeout + provider config fixes

**Released:** 2026-06-04

## Bug fixes

- **Atlassian probe no longer blocks onboarding.** The token validity check used a 10 s HTTP timeout. When Atlassian servers were unreachable, DNS resolution blocked the event loop and cascaded into `/secrets/key-status` also timing out — making Google Workspace detection appear broken and stalling the whole onboarding wizard at 30 s. The probe now uses a 3 s connect/read timeout so it fails fast and the wizard loads normally.

- **Google Workspace detection restored.** The `/secrets/key-status` timeout (caused by the above) was the reason the wizard wasn't showing the Google connected state. No separate code change needed — fixing the Atlassian probe unblocks this.

## New env vars (backwards-compatible)

| Var | Default | Effect |
|-----|---------|--------|
| `GEMINI_CLI_FALLBACK_ENABLED` | `true` | Set `false` to skip the Gemini CLI fallback path |
| `GOOGLE_CLOUD_PROJECT` | `your GCP project` | Substituted into the Vertex API-not-enabled error message |
| `GEMINI_VERTEX_ERROR_SUFFIX` | `or pick a different provider.` | Override the tail line of the Vertex disabled error (e.g. deployment-specific advice) |
