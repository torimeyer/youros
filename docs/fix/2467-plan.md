# →2467: Why prewarm does not cut first-chat TTFT

**Measured on 2026-07-02. Backend bounced ~23:05 local; startup health 40/40.**

---

## Root cause

Three compounding problems:

### 1. Prewarm log is silently suppressed (observability gap)

`_claude_log.info("claude_cli_prewarm_complete")` uses INFO level. The Python
root logger defaults to WARNING (level 30). `myos.chat.claude_code` has no
explicit level set (NOTSET), so it inherits root's WARNING. The INFO message is
filtered before reaching any handler. Prewarm ran successfully every time — we
just couldn't see it.

Fix in this PR: changed to `_claude_log.warning(...)`.

### 2. Prewarm warms the wrong thing (main bug, →2467)

The old prewarm runs `claude -p --output-format stream-json --verbose
--dangerously-skip-permissions "ping"` from `_REPO_ROOT`. This triggers the
full per-turn cost profile — and pays it twice (once at prewarm, once on chat)
because each `claude -p` invocation is a separate subprocess:

| cost component | per-call | prewarm saves? |
|---|---|---|
| binary page cache (cold OS) | ~100 ms | ✅ yes (~50 ms) |
| MCP server init (3 servers) | **405 ms** | ❌ no — servers die with subprocess |
| Anthropic API latency | **4–8 s** | ❌ no — connection dies with subprocess |
| ostk context injection (120 K tokens, 5 turns) | adds ~3.8 s to API time | ❌ no — and prewarm triggered this too |

**Measured timing with the old prewarm shape:**
- `time_to_request_ms`: 455 ms (binary startup + 3 MCP servers spawning)
- `ttft_ms`: 7942 ms total
- Prewarm net savings: ~50 ms out of 7.9 s = 0.6%

**With `--strict-mcp-config` (no MCP servers, baseline):**
- `time_to_request_ms`: 50 ms
- `ttft_ms`: 4149 ms
- This is the floor achievable without a persistent session

**`claude --version` (new prewarm):**
- Wall time: 44 ms, $0, no API call, no MCP servers
- Warms the binary page cache
- No ostk context injection side-effects

### 3. Old prewarm was actively expensive

Each backend restart fired a real Anthropic API call with the ostk MCP context
dump. Measured cost: ~$3 USD per restart. Measured wall time: 62 seconds (5
agentic turns). None of this benefited the subsequent chat call.

---

## Recommended fix (implemented)

Change `prewarm_cli()` to run `claude --version` instead of `claude -p "ping"`:
- 44 ms, $0, no MCP servers, no API call
- Warms the binary in OS page cache (the only thing prewarm can actually save)
- Completion now logged at WARNING level so it's visible in uvicorn output

See: `api/services/claude_code_provider.py` `prewarm_cli()`.

---

## Design-level finding (NOT implemented — out of scope)

To achieve first-chat TTFT < 4 s, a **persistent warm `claude --resume`
subprocess** is needed. A persistent session would:
- Eliminate the 405 ms MCP server respawn on every turn
- Reuse the Anthropic API connection (saves TLS handshake + server warmup)
- Carry prompt cache across turns (the 120 K token ostk context would be a
  one-time cost, not per-turn)

The current fork-per-turn architecture sets a hard floor of ~4 s TTFT
(API latency alone). No amount of binary page-cache warming can address this.
