plan: investigating stale chat model 404

## Root Cause

`api/services/chat_providers.py` — `stream_anthropic()` correctly resolves `_model_id`
from `claude_tier` at line 2463 (e.g. `claude-sonnet-4-6`), but then hardcodes the
retired `claude-sonnet-4-20250514` in every sub-call inside the same function:

- Line 2925: plan-mode creation (`client.messages.create`)
- Lines 3056, 3075: tool-use loop (`client.beta.messages.create`, `client.messages.create`)
- Line 3268: forced-text response after max tool rounds
- Lines 2773, 2783, 3009, 3019, 3184, 3194, 3308, 3318: logging/recording calls (stale but not 404-causing)

`api/services/claude_code_provider.py` line 493: `complete()` default param is also stale.

Additional stale hardcodes in non-chat routers: adventures.py:250, onboarding.py:265,
beautify.py:245, guesswho.py:106.

User settings do NOT contain the stale ID; the bug is purely hardcoded code.

## Fix

1. In `stream_anthropic`, replace all hardcoded `"claude-sonnet-4-20250514"` with `_model_id`.
2. In `claude_code_provider.py`, change default from stale to `"claude-sonnet-4-6"`.
3. In adventures.py, onboarding.py, beautify.py, guesswho.py — replace with `"claude-sonnet-4-6"`.
4. Add settings normalization: on settings read, map retired model IDs to current ones.
5. Add friendly error: if 404 model-not-found, retry with default and surface plain-language message.
