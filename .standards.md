# myOS Coding Standards

Every agent working on myOS must follow these rules.

## Testing
- Run `python3 -m pytest api/tests/ -x -q` before claiming backend changes work
- Run `cd app && npx tsc -b` before claiming frontend changes work
- Run `scripts/run-vitest.sh` for frontend test suite
- Write tests for new features. No shipping without tests.

## Data Safety
- All user data goes to ~/.myos/, never inside the repo
- New stores must be added to test_data_safety.py

## Code Quality
- Python 3.11+: prefer str | None over Optional[str]
- No hardcoded ports (use os.environ.get with defaults)
- No em-dashes in any user-facing text
- Plain language in all UI text, no jargon

## Security
- No secrets in code or commits
- Validate all user input at API boundaries
- No command injection in shell calls

## UI
- Theme-aware colors (use dark: prefix for dark mode)
- All interactive elements need aria labels
- New pages need empty states with guidance
