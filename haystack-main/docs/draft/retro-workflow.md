# Retro: Workflow Inefficiencies (2026-03-07)

> Generated by subagent analysis of 484-exchange session dialog.

## Key Metric

**150+ agent-minutes thinking, zero shipped code from inner agents.**
All 8 releases (6 mish + 2 slipstream) came from orchestrator direct implementation.

## Time Wasted (ranked by impact)

### 1. Babysitting Stuck Agents (~90 min)
Agents on Opus+high-effort thought for 10-35 min producing nothing. 15+ poll cycles consuming orchestrator context. cc2 (21 min, 14 tokens), b4 (34 min, 591 tokens), smish (11 min, 61 tokens).

### 2. Manual Message Relay (~30 min)
Every agent-to-agent message went through the orchestrator. Pure switchboard overhead.

### 3. Paste Mode Bug Workarounds (~20 min)
8+ failed message deliveries. Each required diagnose, retry, sometimes kill+respawn.

### 4. Undirected Exploration (~15 min)
Agents burned context reading files before receiving their task. fs read 11 files (17% context) before getting the actual question.

### 5. BUG-004 Fleet Kill Recovery (~15 min)
/mcp reset killed 5 agents. None had written to disk. Recovery required JSONL transcript archaeology.

## What Worked

1. **Subagent research → direct fix** — 3 Task subagents found exact code paths in 2 min, orchestrator applied 3 fixes in 10 min. 10x faster than autonomous agents.
2. **Surgical prompts** — exact file paths + line numbers + code sketches = agents that work.
3. **Dogfooding as spec discovery** — every failure became a ostk requirement.
4. **Orchestrator doing it directly** — shared mish (6 releases) implemented in ~60 min.

## Recommendations
