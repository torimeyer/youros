You are resuming work on ostk, an llmOS coordination kernel. This prompt provides full orientation for a fresh context.

## What ostk is

A Rust-native invisible OS for AI agents. Single binary (`ostk`). No dependencies. The kernel coordinates agents via filesystem, not messaging. Five laws: invisible write path, ephemeral agents, filesystem coordination, optimistic concurrency, microkernel.

## Architecture (current, post-solid_tui_2)

```
kernel (cpu/)
  ├─ SessionManager — multiplexes AgentSessions
  │   ├─ BootContext (boot.md + .language, 30s refresh)
  │   ├─ build_system_prompt() = agentfile_prompt + boot + .language (~3k tok, cached 1h)
  │   ├─ ApiClient (shared), tokio Runtime (shared)
  │   └─ HashMap<String, AgentSession> with :thread switching
  ├─ AgentSession — per-session: config, messages, CpuEvent channel, kernel identity
  ├─ agent_loop — stateless execution engine (API call → tool exec → repeat)
  └─ squasher — grammar-aware compression pipeline
      ├─ 25 TOML tool grammars (cargo, npm, git, etc.) embedded via include_str!
      ├─ Three-tier classifier (grammar rules → universal patterns → heuristics)
      ├─ Error enrichment (path walk + permissions on failure, 100ms budget)
      └─ compress_with_grammar() in the hot path

fcp-screen (fcp_screen/) — display driver, NOT the agent loop owner
  ├─ 7 ScreenCommand protocol (AppendLine, AppendToken, SetStatus, ShowOverlay, DismissOverlay, Clear, DebugLog)
  ├─ crossterm directly, no ratatui. Three zones: chat (scroll region), input (4 rows), status
  ├─ components/ (dispatch, overlays, session, status, markdown)
  └─ app.rs — 6-param event_loop consuming SessionManager
```

## Design principles

- "The kernel pushes. The screen never polls."
- "fcp-screen is the third thing — not a framework, not an application, a display driver."
- "Buffer diffing IS OCC applied to a display device."
- "The multiplexing lives in the kernel. The screen is a dumb terminal. The smartest dumb terminal."
- System prompt: agentfile_prompt + boot.md + .language. Cached at 10% read cost. All sessions share the prefix.
- Context management: compact_20260112 + clear_tool_uses_20250919 via API betas.
- Agents are ephemeral. The kernel survives. Boot from disk, continue.

## Context management (next frontier)

The Anthropic API provides:
- `context_management.edits[].type: "compact_20260112"` — auto-summarize at token trigger
- `context_management.edits[].type: "clear_tool_uses_20250919"` — clear old tool results, keep last 5
- `cache_control: {"type": "ephemeral", "ttl": "1h"}` — system prompt cached at 10% read cost
- `count_tokens` API — exact pre-call context size

These are configured in agent_loop.rs build_params() via LoopConfig.betas. The scheduler.af declares:
```
BETA context-management
BETA extended-cache-ttl
BETA fast-mode
```

Integration path: SessionManager tracks context pressure via CpuEvent::PreCallTokenCount, displays in status bar. The API handles compaction automatically when configured. Next step: use these to maintain long-running sessions without degradation.
